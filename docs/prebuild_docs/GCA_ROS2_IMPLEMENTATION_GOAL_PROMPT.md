GCA ROS 2 工程生成与代码编写 Goal Prompt
=====================================

本提示词依据 [双轴实现方案](GCA_ROS2_IMPLEMENTATION_PLAN.md)，经设备迁移、ROS 2 运行架构、控制与验证三个 agent 讨论形成。它用于下一轮工程实现，不表示下列代码、测试或接线已经完成。

使用方法：将下方“Goal 正文”至文件末尾作为开发 goal，或要求开发代理完整执行本文件。五个阶段按顺序验收；测试和文档随代码同步完善。无硬件的软件交付与实机验收分别记录。

**Goal 正文**

你正在 `/home/pi/mcrs_ros2_proj` 中工作。请调用多个 agent 讨论并协作，依据 `docs/GCA_ROS2_IMPLEMENTATION_PLAN.md`，实际生成并完成一套基于 ROS 2 的磁控导管／导丝轴向推进与绕轴旋转工程。交付可构建、可安装、可运行、可测试的模块化代码，以及详细易读的中文说明文档。

逐步完成五个阶段：**①舵机和步进驱动 SDK／后端迁移 → ②ROS 2 工程与控制算法 → ③无实物闭环验证 → ④硬件接线说明 → ⑤完整说明文档与最终交付。** 不以再次编写方案、目录骨架、空节点、伪成功返回或未被正式入口使用的代码代替实现。

**执行依据与工作方式**

1. 先读取当前文件和实际环境：`docs/GCA_ROS2_IMPLEMENTATION_PLAN.md`、`docs/ROS_SYSTEM_ARCHITECTURE.md`、`docs/GCA_ARCHITECTURE.md`、`docs/README.md`、适用的 `AGENTS.md`，以及 `legacy/` 中相关源码。历史描述只作定位线索，当前文件、已安装 API 和实际命令结果为准。
2. 双轴部署与实现细节以实现方案为依据；跨端接口、系统单位与 Windows 边界结合系统架构；控制原理结合 GCA 核心设计。发现矛盾时记录问题、依据、取舍和测试，修订相应文档，不能静默删减要求或继承已经被替代的建议。
3. 检查 Pi 型号、架构、内存、系统、Python、ROS 发行版、构建工具与依赖。已有基线为 Pi 4B／ARM64／Ubuntu 24.04／Python 3.12／ROS 2 Jazzy，仍需重新确认。默认沿用现有系统，不为了开始工作升级系统或更换 ROS。
4. 使用多 agent 分工：设备／协议迁移、核心控制／仿真、ROS 接口／运行时／集成，由主 agent 统一接口与合并；按实际并发槽位安排。先约定端口契约和共享类型再并行写代码，划定写入文件范围；交叉审查停止路径、协议、并发和验证结果。所有 agent 对同一工作区负责，避免互相覆盖。
5. 阶段间持续推进，无需对已授权的代码编写和无硬件验证逐次请求确认。以具体文件、命令结果和问题记录汇报进度；遇到失败先定位修复。缺实机资料时记录精确缺口并完成其余软件工作，不能用未知硬件参数填入实机默认配置。
6. 本 goal 默认只执行无硬件开发和验证。不得运行会输出运动的旧脚本、打开真实设备进行试动、自动设零、配置 GPIO、启动实际波形输出或启用实机驱动。实机调试另按用户明确授权和已核实配置进行；本 goal 必须交付其操作说明与验收工具。
7. 保留 `legacy/` 为参考，不将其加入运行时导入路径。构建只发现新工作空间包，测试只收集新测试目录，避免误收集 legacy 中的 ROS 示例、SDK 副本、虚拟环境或带顶层硬件操作的 test 脚本。不得为了测试清理而杀其他任务的进程或删除用户文件。

**工程结构与代码质量要求**

至少交付以下安装完整的软件包；可以在有具体理由时调整内部文件划分，但不得产生两份控制核心：

```text
ros2_ws/src/
  gca_system_interfaces/       # rosidl生成并编译的msg、srv、action
  gca_core/                   # ament_python安装唯一Python包gca
    gca/domain/               # 类型、状态、错误、端口Protocol
    gca/protocols/            # 编码器解析和协议验证
    gca/devices/              # SDK、串口、有限脉冲真实适配器
    gca/acquisition/          # 原始采样、时间和质量
    gca/estimation/           # 标定、参考、回绕与速度估计
    gca/algorithms/           # 轨迹、控制器、脉冲规划
    gca/runtime/              # 状态机、I/O所有者、门控、停止与日志
    gca/simulation/           # 独立plant、模拟设备、故障注入
  gca_ros/                    # LifecycleNode、ROS桥接及CLI入口
  system_coordinator/        # 控制权、系统运动入口与设备许可
  system_bringup/             # launch、参数、配置、部署资源
tests/                       # 跨包协议／集成测试，HIL显式隔离
tools/                       # 安装、验证、仿真报告、标定与诊断工具
docs/                        # 用户、开发者、接线与验收文档
artifacts/                   # 运行生成的报告；有大小管理，不混作源码
```

- ROS 2 是正式运行框架；CLI、手柄和可选非 ROS 入口都通过同一协调器，不持有硬件句柄。纯领域、算法与设备端口不依赖 rclpy，硬件库只在适配器中延迟导入。
- 公开接口使用类型标注、枚举、不可变数据类及明确的返回／错误模型。公共 API docstring 说明单位、前置状态、返回质量、失败行为和线程约束。禁止用无约束字典贯穿控制链路。
- 注释解释线程与资源所有权、锁范围、时钟、单位、协议依据、计数结算、停止证据和状态不变量；必要的数学公式写出量纲及含义。避免只复述代码字面的注释。
- 模块按职责拆分，控制算法不直接操作设备，ROS 回调不承担硬件 I/O。拒绝万能控制类、重复核心、大量全局状态、无实际用途的通用插件框架和逐函数 ROS 节点化。
- 异常不得用宽泛 `except: pass` 吞掉；用稳定错误码和结构化事件记录，令牌等凭证不写入日志。所有队列、重试、设备事务、脉冲排队和关闭流程有明确上限。
- 使用统一依赖、格式化／静态检查和测试配置。核心路径不能保留 `pass`、`NotImplementedError`、TODO 或始终成功的假返回；抽象端口的声明不算空实现，但每个启用的后端必须真实实现契约。后续扩展只记录边界，不以空目录冒充功能。

**阶段 1：舵机、步进驱动 SDK／后端迁移**

先建立最小领域类型、时钟与设备端口，再迁移设备代码；本阶段即可用注入依赖进行测试，不必等待全部 ROS 节点完成。

1. 创建迁移清单，逐项记录“旧文件／旧功能 → 新模块 → 保留或替换理由 → B问题编号 → 测试”。覆盖 DYNAMIXEL 舵机、PUL/DIR 步进后端及用于推进反馈的外部编码器。
2. 舵机采用官方 DYNAMIXEL SDK 的确定版本，封装身份、能力、连接、配置、状态读取、速度输出、停止和关闭；禁止复制多套 SDK 或沿用旧手写舵机协议作为默认实现。核对实际 SDK API、错误语义及超时机制，不给 SDK 函数虚构 deadline 参数。
3. 使用可注入 Port／PacketHandler 工厂等依赖，实现完整真实适配器。模式配置按方案逐步验证：禁止普通输出、核对设备身份、按设备规则确认扭矩禁止、配置并读回模式／限制／watchdog、建立并核对安全零速、仅在显式 ARM 后使能。任一步失败均不得继续使能。
4. 设备读写统一检查通信错误、设备错误、返回长度、型号／ID、数据符号与范围；一次读取只产生一次采样。实现有界超时、错误归一化、重连epoch及部分初始化失败后的资源释放；不能以外层超时包装掩盖仍无限阻塞的底层调用。
5. 旧 DM542 路径没有已确认的厂家“步进 SDK”，应迁移成 `PulseEngine` 和有限定时波形后端。按实现方案优先评估 pigpio 客户端适配；依据官方 API 编写 submit／poll／abort／close及能力声明，软件测试使用注入波形客户端，不启动真实输出。
6. 禁止用 Python sleep、ROS timer 或无限重复波形逐脉冲驱动；区分 planned／reserved／confirmed 计数，处理段ID、epoch和代次。接受、忙闲和SDK返回值不冒充已输出数；中止无法结算时返回未知并作废估计。平台不支持或能力未验证必须明确拒绝硬件启用，不能静默切换仿真。
7. 编码器实现真实有界串口事务与增量解析：CRC固定两字节、精确长度、地址／功能码／异常响应、请求关联、迟到帧隔离、原始计数与数据质量。计数范围、负数解释和回绕规则未知时要求型号配置，不硬编码旧900／1800圈假设。
8. 将实现方案中的两条协议缺陷证据纳入黄金回归：编码器CRC高字节为零的报文；合法CRC但无位置参数的舵机状态帧不得被当作位置。再覆盖坏帧、超时、写失败、错误读回、旧非零速度残留、重连、取消和清理。
9. 输出依赖来源、版本、平台条件和许可记录。核对第三方实际许可证，保留适用声明；旧自研目录的LICENSE含模板介绍，不能仅凭文件名为其指定许可。不得复制legacy虚拟环境或随意重标许可证。

阶段完成证据：真实适配器代码、模拟SDK／串口／波形客户端测试、依赖清单、迁移表与配置schema均落地，测试真实适配器的正常及失败路径。无实机不能成为只交付接口空壳的理由；未知设备能力需显式未验证并禁止 ARM。

**阶段 2：ROS 2 代码编写与控制算法实现**

实际生成 IDL、包清单、安装规则、节点、launch、参数、客户端和运行时，完成以下运行链路：

```text
CLI／手柄／上位机
  → system_coordinator（会话、权限、模式、系统任务）
  → gca_control_node（Lifecycle、Action及状态桥接）
  → 本地控制任务（轨迹、控制器、输出门控）
  → 设备I/O所有者／真实或模拟适配器
  → 采样、执行回执、状态、Action反馈和结果
```

1. 保留系统文档的命名空间与单位契约。实现系统层领取／续期／释放控制权、ARM／DISARM／RESET／STOP、参考设置和GCA-only运动入口，接通设备侧执行许可、续租及管理接口。不能只声明 `/gca/*` 而缺少协调器到设备的实际调用路径。
2. 本轮明确交付GCA-only运行配置，可新增并文档化 `/system/execute_motion`，使用明确的Action定义；上位机经过协调器再调用 `/gca/execute_motion`。既有 `/system/execute` 的完整磁驱动实验契约保持边界，不能静默将联合实验改为只动GCA。Windows真实电流控制、严格同步、视觉／力反馈、磁场反演、ros2_control迁移及新增MCU属于后续扩展，不阻塞本轮五阶段交付。
3. 实现单轴／双轴绝对及相对定位、短租约Jog、STOP、HOLD、DISARM、故障锁存／RESET、显式参考、能力与质量状态、记录与查询。axis_mask只检查所选轴必要能力，未选轴必须停止且不能继承旧HOLD；双轴一次准入，不允许半边接受。
4. ROS使用m／rad／s，核心使用mm／deg，转换只发生一次；方向、计数和设备单位封装在设备边界。外部编码器测量是推进反馈，舵机自身位置仅用于诊断；无效值不得变为0或目标值。
5. 实现速度／加速度受限轨迹、带实际采样dt的P／PI／可选D控制、速度估计和滤波、限幅／边界制动、最终输出抗饱和、轨迹完成且误差／速度驻留达标的到位判断。重复快照不重复积分；异步回执只追加设备量化与已限幅值的残差，按输出序号结算一次，不重复回算。旧PID参数不作为新版实机默认值。
6. 实现开环旋转的累计角度、绝对脉冲舍入、细小增量余量、加减速、换向约束、有限段、预约与完成结算。完成条件是量化目标脉冲满足、后端idle且无未结算段；估计失效后拒绝依赖累计参考的绝对／相对定位，不虚构实际角度反馈。
7. 单一本地控制任务写运动状态；每物理总线一个I/O所有者。ROS回调不等串口、不等运动、不逐脉冲输出；本地控制不等磁盘或DDS。I/O独立检查TTL、反馈原始年龄、设备epoch、授权generation、本地output_generation、参考和配置版本；旧续租、旧样本或遥测存活不能维持旧动作。
8. `Lifecycle ACTIVE`、ARM、控制会话与参考分别检查。configure不自动运动或设零，activate保持DISARMED；deactivate先撤销输出再有界等待本地停止，不能等待被自身回调阻塞的ROS Future。故障和inactive仍可观察状态并请求授权停止。
9. 严格实现方案中的Action reservation／Future／guard桥接：Future先登记，后投递StartRequested，再调用goal_handle.execute；execute仅异步等待结果。请求、取消和结果提交同组串行；核心只产候选结果，桥接唯一提交终态。原生取消进入CANCELING后才能canceled，取消超时或停止未知则失败，成功和取消不得双终态。
10. 预留目标槽和所有等待有期限；异常路径释放。相对目标只转换一次；command_id去重、载荷冲突检查和sequence高水位实际生效。原生目标拒绝仅有接受布尔，详细原因由关联查询／事件提供。
11. end_policy定义UNSPECIFIED=0／STOP=1／HOLD=2，拒绝0。HOLD使用独立保持上下文，本地代次不能延长或迁移外部授权；到位后仍检查反馈、源控制权和执行许可。STOP使用独立受限路径，普通token过期／反馈无效时仍能停车，停止确认需要适当证据，不能以SDK写零速成功代替。
12. 配置采用完整schema及requested／applied版本。on_set只校验，post_set只排队，初始declare同样校验；关键变更仅DISARMED且无任务／预留，ARM要求配置已成功应用。任何部分配置失败不能使能。硬件示例缺必需项即拒绝ARM。
13. Jog只在新鲜输入且deadman使能成立时续期；松开、拔出、异常、输入线程死亡和退出不能续旧速度。处理SIGINT／SIGTERM、部分初始化、节点退出和重启，始终先有界停止与结算，再释放资源。
14. QoS、队列、日志与状态符合方案：运动命令不使用TRANSIENT_LOCAL，连续目标容量1，关键完成与故障不可静默丢失，日志异步有界。区分应用会话与身份认证，直接GCA接口和原生CancelGoal也在权限范围内；跨机访问若启用，要落实并测试部署权限，不能把ROS_DOMAIN_ID或owner字符串当认证。

阶段完成证据：新包和IDL真实编译、安装，正式CLI通过协调器完成配置／激活、控制权、设参考、ARM、双轴动作、反馈、结果、取消、停止与释放；未ARM请求被拒绝。不得依赖手工PYTHONPATH或从源码目录直接运行掩盖安装缺失。

**阶段 3：无实物闭环验证**

1. 实现独立plant。它只能消费实际提交并被模拟执行器接受的输出，按自身状态与时间更新位置；不得读取目标后直接赋值，也不得将参考轨迹当测量。模拟舵机包含滞后、饱和、摩擦／死区及可配置滑移，编码器独立采样并包含量化、噪声和延迟；参数明确属于仿真。
2. 旋转分别维护请求、预约、确认脉冲与独立模拟机械角度。机械角度只用于评估开环误差，不接入真实系统不存在的角反馈。可模拟失步，但不能要求或宣称开环软件自动检测一切不可观测失步。
3. 确定性测试使用可注入单调时钟与固定种子；竞态用事件／屏障／受控调度安排顺序，不能仅靠sleep偶然通过。测试预期来自契约、独立模型和已知报文，不复制被测实现。
4. 启动真实ROS 2节点进程，通过实际DDS、Lifecycle、Service、Action和Topic完成集成；只有设备和plant用模拟后端。测试系统公共入口、设备入口许可、领取／续租、未ARM拒绝、单轴／双轴、取消、Jog、HOLD、STOP、故障与恢复、进程退出。禁止仅mock rclpy或直接调用内部函数就声称ROS联调完成。
5. 完整覆盖实现方案T01–T18，并建立B01–B20→修复代码→具体测试→实际运行证据→HIL依赖的追踪矩阵。不能以跳过必需软件测试形成“全通过”；与硬件无关的失败必须修复。
6. 故障覆盖编码器断开／冻结／跳变／旧帧、CRC及短帧错误、SDK失败、零速接受但plant仍运动、控制任务冻结但遥测继续、executor失效时本地期限、租约到期、旧epoch／代次／回执、取消和成功竞争、脉冲中止计数未知、满队列、慢盘／慢订阅、重连与节点重启。逐例断言状态、输出行为、停止证据及恢复条件。
7. 生成机器可读结果和离线图表，保留版本／配置摘要、种子、任务ID、目标／参考／反馈／输出曲线、误差／超调／到位时间、停止响应及异常事件。模型时间与实际ROS进程墙钟测量分开报告；仿真指标采用明确仿真阈值，不宣称实机性能或经过证明的最坏停止上界。
8. 真实SDK、串口、波形适配器仍须被测试：注入依赖检查实际代码路径、调用序列、错误、超时、中止与资源释放，不能只测模拟后端。无依赖／不支持平台测试应与已安装依赖下的离线测试分别覆盖。
9. 使用隔离测试命名空间与适当ROS domain；默认测试不打开真实串口、不设置GPIO、不启动硬件守护进程、不import旧硬件脚本。退出只清理本次创建的进程和文件。
10. H01–H03列入独立HIL计划，当前未执行记录为NOT_RUN，附设备、仪器、步骤、待确认目标和证据模板。无硬件软件测试通过不证明接线、电气兼容、波形、真实角度、停止距离或整机性能。

阶段完成证据：完整测试命令与退出码、通过／失败／跳过数量、JUnit或等价结果、仿真原始记录和图表、B/T/H追踪表。仅compileall、import成功、空测试或一次顺利动作不能代替此阶段。

**阶段 4：硬件接线说明**

完成 `docs/HARDWARE_WIRING.md`，包含可读连接图、设备／接口清单、引脚／端子表、电源与信号说明、软件配置映射、上电前检查及HIL准备。目标是让读者理解当前已知接法与待核实条件，而不是把未知连接画成已验证电路。

1. 覆盖Pi→匹配物理接口的DYNAMIXEL转换器→舵机，Pi→编码器接口，Pi→经核实的PUL／DIR／可选EN接口→步进驱动→电机，以及电源、接地／隔离、禁止输出或已存在的硬件急停通路。
2. 每条关键连接和参数注明证据来源及状态：旧代码线索、官方资料确认、待实物核实、实测验证。需要新增技术事实时核对对应型号官方手册并记录链接、型号／版本／页码；没有资料不得猜测。
3. 明确BOARD物理引脚、BCM编号和配置字段的对应关系。旧BOARD29／31只作PUL／DIR线索，不直接传给BCM接口；核对板型与接线图后记录映射。
4. `/dev/ttySC1`与38400不能证明编码器是TTL还是RS-485；舵机TTL／RS-485、转换器、供电和连接器也必须依型号核实。不得仅凭软件串口路径确定电气接线。
5. 旧代码有6400与25600脉冲相关配置，需解释冲突并核对细分拨码、驱动型号、实际脉冲／圈与传动比；轮径、方向、行程和停止距离均进入标定表，不继承为已测参数。
6. 未确认输入电压、电流、光耦、电平转换、共阳／共阴／差分或EN极性时，使用条件连接图和待确认端子表，指出定案需要的资料；不能断言Pi GPIO可直接连接任意PUL±／DIR±。不得虚构已安装的限位／原点／急停器件。
7. 文档区分软件STOP、扭矩／使能禁止和独立硬件急停，以及各自能证明的状态。提供断电核线、只读身份检查、低速方向／比例确认、波形有效沿／DIR时序测量、取消／失联停止、外部位移／角度测量和标定记录步骤；当前只交付步骤与工具，不执行实机动作。

阶段完成证据：接线图、表、配置字段和设备清单一致；有来源与未确认项表，所有未知电气条件明确，HIL步骤能被后续操作者按顺序执行。待实物核实可以保留，但不得只交付一句“接线待定”或以候选连接冒充实测确认。

提供并实际验证三个统一工具入口，文件名固定如下；内部按项目实际实现：

```bash
# 均从项目根目录执行；默认无硬件输出
bash tools/bootstrap_dev.sh
bash tools/verify_software.sh
bash tools/run_simulation_suite.sh --output artifacts/simulation/latest
```

- bootstrap负责可复现的开发环境准备和依赖检查；按当前权限安装或明确报告缺项，不更换系统、不启动硬件，不悄悄污染不相关Python环境。

- 除日常symlink-install构建，还须在独立输出目录进行一次普通安装验证；从工作空间外的新终端仅加载ROS underlay及本次install，验证CLI、launch、配置和资源可用。不能依赖旧overlay、手工PYTHONPATH或当前源码目录。
- 仿真示例可以显式通过CLI发出模拟ARM和运动；普通launch仍保持DISARMED，不能将自动ARM扩散到hardware配置。

由未主写对应模块的agent复审SDK／协议、Action与停止竞态、闭环真实性、测试覆盖和文档。主agent处理问题后再次执行受影响验证，并检查全部要求的证据，不以agent口头通过代替测试。
