## 按键分工

| 手柄输入 | 功能 | 归属 |
|---|---|---|
| 左摇杆上下（LY） | 推进／后退速度；上推为推进，下拉为后退 | GCA |
| 左摇杆左右（LX） | 正向／反向旋转速度；方向映射可配置 | GCA |
| LT，左扳机 | 按住才允许左摇杆产生运动，松开停车 | GCA双轴deadman |
| B | 软件STOP，优先于LT和摇杆输入 | 当前GCA停止入口 |
| RT，右扳机 | 预留磁场控制，具体功能待定义 | 磁场 |
| RB，右肩键 | 预留磁场控制，具体功能待定义 | 磁场 |
| 右摇杆RX／RY及按下RS | 预留磁场控制，具体功能待定义 | 磁场 |
| LB、左摇杆按下LS及其它按钮 | 暂不分配功能 | 待定义 |

旋转“正向”沿用工程坐标定义，其实际观察方向须随机构标定确认。摇杆输出经死区处理后按幅度映射速度，回中为零；不映射为累计位置目标。斜向推动左摇杆允许两轴同时运动，各轴分别限速。原始轴编号、符号及扳机范围由所选驱动与实际手柄核对，统一在输入适配边界转换，不照搬legacy的索引。

## LT与停止行为

LT作为允许运动条件，不承担速度调节，也不等于ARM。需要先具备MANUAL控制会话、有效参考、已应用配置及显式ARM，才能接收摇杆运动。ARM和参考设置使用现有系统管理接口；手柄实施方案增加同一owner的本机管理代理，避免另一CLI争抢控制权，不占用预留给磁场的右侧按键。

LT为模拟输入时，适配层应先按已确认范围归一化，再用可配置的按下/释放阈值判断；按下阈值高于释放阈值，避免临界抖动。阈值属于待实现的手柄配置，尚无实测默认值。释放、无效读数或断连均撤销运动输出并停止更新Jog许可，不能维持上一次速度；源控制会话的续租不等于速度命令可以续期。

待实现的手柄状态逻辑遵循以下约定：

1. 连接、重连或重新取得控制权后，先确认LT释放且左摇杆回中，再接受新的LT按下；不自动ARM或重建参考。
2. B优先处理，清空待发速度并请求STOP；B按住期间不能发出新的运动。释放B不会自动恢复，需LT释放、左摇杆回中后再按LT。
3. 松开LT、拔出手柄、采集失效或客户端退出时请求停止，停止更新运动许可；旧输出同时受既有TTL和租约约束。不能用缓存摇杆值持续续期，也不能仅以重复发布的消息证明实体手柄仍在线。
4. STOP的受理与停止确认分别处理。停止未知、故障锁存或旋转参考失效时，按既有恢复流程处理，手柄不得自动清故障、设零或恢复历史运动。

## 接入现有接口

拟新增的手柄适配节点将输入转换为 `gca_system_interfaces/msg/JogCommand`，经 `/system/manual_target` 进入协调器。LY对应 `linear_velocity_m_s`，LX对应 `rotation_velocity_rad_s`，LT对应有效输入条件下的 `deadman`，双轴掩码为3。每次有效运动还需完整命令上下文和短期运动许可，不能直接把原始Joy消息转发到设备层。

LT释放可发送 `deadman=false`；B调用 `/system/request_stop`。状态和停止确认读取 `/system/state`。这些接口已存在，具体字段与权限见 [ROS接口](ROS_INTERFACES.md)；手柄连续采集、映射及断连适配仍需实现。

右侧磁场输入在当前GCA-only配置中不产生GCA运动或管理请求。磁场接入后应由同一操作者会话统一分发两类意图，避免两个输入节点竞争当前唯一控制权；磁场命令接口及B的联合停机策略需随系统联锁明确。现阶段B请求的是GCA停止，尚无已实现的磁场停机效果。

## 后续验证

软件回归需覆盖LY/LX方向、独立死区、斜向双轴、LT阈值抖动、B与LT同时按下、停止后不自动恢复，以及RT/RB/右摇杆不会触发任何GCA请求。再通过真实ROS仿真验证许可过期、采集停止、断连与重连的停止路径。

实体手柄识别、轴范围、按键映射和拔出行为按 [H03](HIL_ACCEPTANCE.md) 验证，当前均为NOT_RUN；既有CLI Jog测试不能代替实体手柄验收。

当前已识别北通接收器及joydev静态能力，物理按键和无线失联响应仍未采集。USB接收器在线不等于无线手柄在线；默认event_age模式在静态长保持时会超时停车。允许持续保持的qualified_state模式需匹配实际输入资格记录，具体边界见实施方案。
