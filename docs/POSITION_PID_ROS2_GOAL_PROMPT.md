# ROS2 上位机位移 PID 闭环实施 goal prompt

以下内容用于后续实施任务。本文件保存不代表已经启动实施或实机运动。

---

请在当前工程实现基于 ROS2 的上位机单轴位移 PID 闭环控制。先阅读 `docs/POSITION_PID_ROS2_PLAN.md`、`docs/CONFIGURATION_AND_CALIBRATION.md`、现有舵机用户指南及对应代码。调用多 agent 分别检查运行时、编码器/PID、ROS 接口，收敛接口后分工实现；不得相互覆盖修改。

目标是让上位机提交绝对位置或相对位移，树莓派使用外部编码器真实反馈修正舵机转速，正确报告到位、取消、失败和停车。手柄继续原生 RPM 开环，不使用外部编码器反馈修正，不依赖编码器在线。代码应简单、鲁棒、易维护；复用当前实现，只改本任务需要的部分。

## 一、固定边界

1. 提供明确的手柄/上位机控制开关 `control_mode:=manual|position`，保留 `MANUAL_SERVO_VELOCITY`，实现 `POSITION_EXTERNAL_ENCODER`。两种启动装配互斥运行，共用 `ServoControlNode`、`FeedAxisRuntime`、唯一舵机 I/O 所有者和 STOP，不复制完整运行时。
2. 手柄入口不创建、打开或读取外部编码器；保留 LY 调速、LT 持续使能、B 停止及现有恢复规则。位置入口不要求手柄输入质量或 LT。
3. 位置装配在 configure 阶段启动独立编码器采集，DISARMED 时可建立参考。切换采用 STOP 确认、DISARM、释放会话、退出旧入口、启动新入口；不实现同进程热切换。
4. 首期仅 LINEAR、ABSOLUTE/RELATIVE、单活动任务、STOP 结尾；拒绝 HOLD、任务队列、运动中替换、双轴和磁场联动。不要新建位移 Topic、第二套控制权或通用策略插件框架。

### 模式开关必须可使用和可查询

实现统一 `system_bringup/feed_axis.launch.py`，显式必填 `control_mode`，独立选择 `backend`。旧手柄 launch 固定映射到 `manual`，位置入口映射到 `position`，共用装配代码。模式写入不可变配置快照，启动参数必须匹配；非法值或不匹配在连接硬件前拒绝，不按是否存在编码器自动猜测模式。

明确映射 `manual → ControlSession.MANUAL → MANUAL_SERVO_VELOCITY`、`position → ControlSession.AUTO → POSITION_EXTERNAL_ENCODER`。协调器、设备节点、核心共同限制准入：手柄模式拒绝 AUTO 位移任务，位置模式拒绝 MANUAL 会话及手柄 Jog。不能只通过“不启动另一输入节点”实现互斥。

通过已有 `/system/state` 的 `control_policy`、会话和 armed 状态显示实际模式；不增加仅为查询模式的服务。运行时模式参数只读，切换必须完成旧装配 STOP 确认、DISARM、释放和退出后重启。停止未知或设备未释放时不能接管，不使用强制杀进程/抢锁完成切换。新模式保持未使能；进入位置模式重新 reference，回到手柄模式要求释放 LT、回中并按原流程使能。首期提供启动选择和停机后切换，不承诺运动中即时接管。

### 功能包与模块责任

沿用现有六个包并新增 `gca_position`、`gca_client`，不要把新增业务集中到 `gca_ros` 或 `gca_core`：

- `gca_system_interfaces`：仅 IDL；`gca_core`：无 ROS 的公共算法、领域契约、运行时基础及已有驱动，不导入新位置包。
- `gca_position`：无 `rclpy` 的位置业务库；`strategy.py` 放轨迹/PID/到位，`feedback.py` 放计数估计适配/参考/速度窗口，`acquisition.py` 放复用 `SerialEncoder` 的采集所有者。共同依赖 `gca_core`，不复制驱动或算法。
- `gca_ros`：设备侧 ROS 适配和组件装配，将位置策略/采集对象通过核心 Protocol 注入 `FeedAxisRuntime`。不得让核心反向导入位置实现或位置包配置类型。
- `system_coordinator`：模式准入、会话、许可与任务代理；`gca_teleop`：手柄输入和 MANUAL 控制；均不放位置 PID 或串口读写。
- `gca_client`：上位机持久客户端及 CLI，迁入现有客户端逻辑，依赖 `rclpy`、接口和生命周期消息等客户端库，不依赖 `gca_ros`、协调器实现或硬件驱动。客户端消息转换在客户端边界完成；不能继续导入 `gca_ros.conversion.quality_to_ros` 或为少量数据字段依赖含硬件的核心包。
- `system_bringup`：统一模式开关、节点装配和退出管理，不计算控制量。

旧 `gca_ros.cli` 保留薄兼容入口和已有公开符号，如 `GcaClient`、`Credentials`、`finite_float`、`save_credentials`，不得复制新客户端实现。依赖可为 `gca_ros → gca_client`，不得反向形成循环。更新每个包的 manifest、安装入口及必要依赖，客户端应可单独安装。此次不全面搬迁旧驱动或重构旧双轴实现。

包划分不意味着新增进程：PID、反馈和串口所有者保持在设备进程内，通过有界对象交换；不为每个算法或设备另建 ROS 节点。

## 二、配置和已有事实

以 `config/servo_settings.py` 和 `config/encoder_settings.py` 为唯一人工参数来源，不另抄一份常量。新增组合导出工具和严格、带摘要的位置运行快照，继续使用 `servo_config_file`；模式由导出工具显式选项传入，保证 `control_mode` 与固定策略一致，运行时不执行配置脚本。保留旧手柄快照兼容，位置关键字段错误须显式拒绝，不回退为手柄模式。

当前参数必须保留：

- 舵机驱动轮半径 6 mm、直驱，几何比例 `2π×6 mm/输出轴圈`；正推进对应负 RPM。手柄原生速度及加速度上限保持现状。
- 编码器 `BRT38-ROM-4096-D1800-RT1-IP68`，RS485 `/dev/ttySC1`、38400、8N1、地址 1，功能码 03 读寄存器 0～1；32 位无符号、高位在前。
- 编码器测量轮半径 10.89 mm、直连、4096 count/圈、循环 7,372,800；按用户选择采用理论 `mm_per_count`，正推进计数增加。不得重新要求先实测标定才能实现。
- 编码器读取 20 ms、事务超时 50 ms、反馈有效期 100 ms、重连静默等待 100 ms；异常速度阈值自动取位移限速的 1.5 倍，当前 15 mm/s。
- 位移速度上限 10 mm/s、加速度上限 10 mm/s²；行程 −50～1000 mm、边界余量 10 mm；允许目标与边界制动保持一致，为 −40～990 mm。
- `kp=2, ki=0, kd=0, kaw=2`，积分限幅 1 mm/s，PID 最大相邻有效样本间隔 0.2 s；保持工程初值属性，不自动调参。
- 误差 ≤1 mm、外部速度绝对值 ≤0.1 mm/s，连续 0.3 s 才满足到位条件。
- 实测刹车减速度及延迟的原值保持 `None`，通过现有解析器采用 5 mm/s²、0.5 s 缺省值并记录来源，不因此阻塞实现，也不宣称已实测。

仅新增必要的 `estimation.velocity_window_s=0.2` 到编码器独立配置，用于位置策略速度估计。当前约 2 秒、100 次成功查询的证据在 `artifacts/encoder_readonly/timing-7x7x_4_p/`，不要重复串口压力测试。

## 三、纯 Python 核心

在 `gca_position` 新增位置策略组件，复用 `LinearEstimator` 的计数展开和参考、`Trapezoid`、`PositionController`、`MechanicalMapping` 及 `resolve_braking_parameters`。策略模块不包含 ROS、串口或授权代码，采集模块独立持有编码器串口。

编码器线程复用 `SerialEncoder`，一次只允许一个未完成请求，通过有界最新样本交换与故障事件交给控制线程。采集错误必须明确传播；不能把估计器返回的旧 valid 状态当成新反馈。

计数和速度使用原始采样时间，保留请求起始时间用于保守计龄和诊断，不以 ROS 发布或重复读取缓存更新时间。每个新消费样本最多更新一次 PID，序号单调即可，不要求连续加 1。初期保留控制线程 40 ms 周期与编码器 20 ms 周期，允许消费最新样本时跳过中间样本。

位置模式使用约 0.2 s 的有界速度窗口，以展开后位移差除以实际时间差。窗口不足或采集断档、失效、epoch/参考改变时速度无效；不得填零伪造停稳。保持旧双轴估计器默认行为。

控制输出为 `v_ref + kp*(x_ref-x) + I - kd*v`，单位 mm/s。经过目标/全局速度限制、实际输出 dt 的加速度限制、边界制动后，由机械方向与几何比例换算 RPM，交给原舵机 I/O。量化后的实际提交目标也不得超过位置速度限制，不能因向上舍入而超限；复用现有量化实现并保留手柄语义。软件限幅回算一次，实际接受值的量化残差回算一次；重复、过期、跨代回执拒绝。不得叠加第二个外部速度 PI。

参考在显式调用时由新鲜编码器位置建立，不写硬件置零。位移通式为 `x_mm = reference_position_mm + direction_sign * mm_per_count * (unwrapped_count - reference_count)`，支持非零参考坐标。相对目标正式接纳时解析一次，绝对目标使用匹配参考；同一运行期间多个任务共用固定参考。退出位置装配、设备重连或 epoch 改变使旧参考与任务失效，恢复后显式 reference、ARM 和提交新目标，不续跑旧任务。

## 四、运行时及期限

检查并按策略改造 `FeedAxisRuntime` 的 ARM、`_valid_output`、`_enable_allowed`、最终写入条件和现有位置占位接口。位置分支检查 AUTO 许可、任务、参考及外部反馈，不检查手柄 `_input_deadline`、LT 或伪造 quality。状态只有控制所有者写入，故障撤销门控可由 I/O 独立置位。

位置输出保留它实际使用的编码器 seq、原时间、epoch、reference_id 和固定输出截止。最终发送前同时检查原反馈新鲜度、当前采集健康、任务/授权代次及 STOP 屏障，不用最新样本时间为旧 PID 输出续期。

保留完整舵机事务预算 80 ms、舵机反馈年龄 250 ms 和输出 TTL 300 ms。编码器 100 ms 是独立的新鲜度判据，不能把它覆盖到舵机时序，也不能要求完整 80 ms ACK 必须落在编码器剩余年龄内。发送前检查通过后，已开始事务按其有界截止结束；STOP 可同时撤销后续输出，事务退出后优先零速/关力矩。不要通过无限延长旧输出或截短串口等待来解决间断。

舵机 I/O 独立检查引用的编码器反馈及输出期限，控制线程停滞时仍能停车。编码器失败、过期、跳变、重连以及失去会话触发位置 STOP；不得自动降级为开环继续运动。

## 五、到位和终态

轨迹结束且误差进入 1 mm 容差时，先令位置目标速度归零并按限制减速。正式 STOP 前若误差超限，可继续修正同一目标。仅新鲜、不同序号、速度窗口有效的样本，连续满足位置和速度条件 0.3 s，才进入正常完成的 STOP。

正常成功必须同时具备新鲜舵机停止证据和仍满足最终位置/速度条件的编码器反馈，返回 `outputs_held=false`。正式 STOP 后条件失败则任务失败，不自动恢复运动。

Cancel、外部 STOP、任务超时和故障立即撤输出，不等待到位驻留。继续使用现有 Action 取消握手、唯一终态和 STOP 屏障。编码器失效时可以报告舵机已停，但不能报告外部位移已停或到位成功。

## 六、ROS2 和上位机

复用 `/system/execute_motion → /gca/execute_motion`、控制权领取/续租/释放、set_reference、ARM/DISARM、request_stop、get_command_status。按已认证 AUTO 会话绑定位置策略，不允许普通消息自报模式切换。

ROS 使用 m、m/s、m/s²，核心使用 mm、mm/s、mm/s²；设备侧仅在 `gca_ros/conversion.py` 转换，客户端用户单位在 `gca_client` 边界转换为 ROS 单位，不依赖服务端转换模块。迁移并扩展 `GcaClient` 的明确线性调用方式：LINEAR 掩码、旋转零值、线性参考、速度与加速度不超过 capabilities；不能沿用现有双轴/20°/50 mm/s²默认值。使用持久客户端自动续租、等待 Action 结果和清理，不让用户手工拼接 token 或 generation。

位置模式的线位移、速度、有效性、反馈年龄和身份来自外部编码器；舵机轴数据保留在嵌套 ServoState，停止证据分开。复用已有能力字段，只在配置和装配支持时开放线性能力；手柄模式仍不宣称能测外部位移。

统一模式入口支持 simulation/hardware，兼容 launch 仅作薄封装，不自动 claim、reference、ARM 或运动；位置入口不启动手柄 owner。提供明确的本机/局域网发现配置，不无条件固定 LOCALHOST。双方 ROS_DOMAIN_ID 一致，保持既有授权；远程时钟不与树莓派单调时钟比较。上位机首期为 ROS2 客户端，不新增 TCP 网关。

MANUAL 的 LT/B 行为保持现状。AUTO 使用上位机 STOP 和 Action cancel；不要宣称 B 已具备跨所有者的全局 STOP 权限。

## 七、验证预算

只执行与改动相关的定向测试、受影响的关键旧路径回归，以及一次正式安装后的 ROS 仿真联调。不要默认运行整个历史测试集，不新增镜像实现的测试，不追求覆盖率数字。通过后停止追加；失败先定位，只重测修复涉及的项目。

必要软件行为可合并为少量参数化用例：

1. 配置及单位/方向、绝对和相对目标、参考/边界/重复命令；合并验证模式未指定/非法、不匹配、错误来源命令拒绝、切换后未使能及旧任务不恢复。
2. 新样本一次更新、回绕、单计数噪声下的停稳、速度窗口失效和重建。
3. 编码器错误/过期/epoch 改变、会话失效、取消与成功竞争、STOP 后旧命令/回执不恢复运动；100 ms 新鲜度与 80 ms 完整事务预算分离。
4. MANUAL 无编码器仍可用，位置分支不要求手柄输入；现有 LT/B 关键回归保持通过。

增加最小包依赖/导入检查和旧 CLI 兼容检查，确认没有 `gca_core ↔ gca_position` 或 `gca_ros ↔ gca_client` 循环，客户端不需导入设备包。模式与模块化检查合并到软件验证，不为此增加实机轮次。

ROS 仿真只启动一次，脚本设置有限总超时，合并正反向绝对/相对任务、到位 STOP、一次取消和一个固定滑移工况。模拟反馈由实际接受的舵机输出经过机构模型产生，不直接把目标赋给反馈；必要故障在软件注入，不逐项实物制造。

现场条件具备时最多一组短程实机：相对 +5 mm，再绝对回到 0 mm；速度 2 mm/s、加速度不超过 5 mm/s²，每个任务最多 10 s。只补问确实缺失的机构接合、可用行程和操作者在场信息，不重新索要已经明确的参数或授权。没有对应编码器变化、方向错误或意外中断立即 STOP 并结束该组，先分析日志。不要反复操作直到偶然通过，也不要重做无线资格、手柄映射、长期压力和已延期的总线静默专项。

实机和跨机条件不足时，完成不依赖它们的软件及文档，明确列出 NOT_RUN 和具体缺项；不能宣称实机或跨机已经验收，也不能无限等待现场输入。

## 八、交付与完成判定

提供可运行的组合配置导出、`control_mode:=manual|position` 启动、当前模式查询、停机后切换、仿真/硬件启动、上位机持久客户端示例、参考设置、绝对/相对移动、取消/STOP、正常退出和记录查看命令。说明各功能包职责与依赖，提供客户端独立安装方式；示例必须对应实际安装后的入口，不能只写概念伪命令。

日志沿用有界异步 JSONL，记录目标/实测位置、误差、窗口速度和有效性、原始计数及时间/seq/epoch、PID 使用的样本、请求/限幅/接受输出、实测 RPM、制动参数来源、停止原因及 Action 终态。不记录授权 token。

更新本方案、配置说明、ROS 接口、用户指南及实现状态，保留既有未提交工作。不要自动提交或推送，除非用户另有指示。软件实现、ROS 仿真、实机和跨机通信分别报告 PASS/FAIL/NOT_RUN，附证据和实际限制；已通过的范围不再追加测试。尚未验证的几何比例、制动缺省值和故障时延如实记录，不通过新增繁琐审批或伪造通过来处理。
