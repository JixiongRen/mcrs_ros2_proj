## 一、需求与范围

## 三、独立配置与原生舵机驱动

新增工程根目录 `config/servo_settings.py`，作为舵机数值配置的唯一人工编辑入口。只依赖 Python 标准库，导入、显示、校验和导出均不打开串口、不导入 ROS。导出带 schema、修订号和摘要的严格 JSON 快照；ROS 和独立诊断程序加载同一快照，不动态执行配置脚本，不另维护重复 YAML。修改数值后重新导出并重新配置，无需重编译 ROS 消息。

配置分开表达：设备身份和厂家单位；手柄方向及速度上限；速度变化率、串口事务期限、反馈最大年龄、命令期限、停止确认期限和非零 Bus Watchdog；未来机构标定和 PID 参数。未知机构参数明确不可用，不使用仿真默认值冒充标定。错误类型、未知字段、非有限数、越界值及相互冲突的时间预算均明确拒绝。

方向和单位约定：

- 使用现有死区和响应曲线后的 `mapped.ly`，手柄适配层唯一执行 `servo_rpm = -mapped.ly * max_rpm`；原生驱动不再反向，Drive Mode 必须核对。
- 核心／驱动使用 RPM；ROS 舵机速度使用 rad/s，在 ROS 边界转换。速度寄存器按已核对的 `0.229 rpm/raw` 换算；轴计数与输出轴角度按已核对的 `4096 count/rev` 换算，并声明参考和有效性。
- 手柄反向系数与未来机构正位移方向是两个不同事实。未来 mm/转和机械方向均须实测，不把“上推反转”当作真实机构标定。
- 首次低速调试可采用原始速度上限 20（4.58 rpm）作为候选上限，明确它尚未通过速度模式验证。加速度和各项时限须依据实际事务预算确定并记录，不照搬仿真 10 ms 周期或把候选值写成实测值。

提取 `DynamixelVelocityDrive`，提供设备识别、速度模式配置、RPM 写入、原生轴状态读取、力矩管理、停止和关闭。复用 `sdk_support.py` 的单调时钟期限、响应身份／长度校验和设备锁，增加串口独占。现有线速度适配器包装共用驱动并负责旧毫米换算，避免复制一套串口实现；迁移时检查旧路径行为。

配置或调参只能在 STOP 已确认、DISARM 后应用，同时撤销旧许可和待发输出。禁止运动中修改全局变量或热切换配置。设备字段语义、协议细节或真实标定不明确时先核对代码、原始报告及厂家资料；仍不明确则提出具体问题，不写猜测性兼容分支。

## 五、授权、初始化和停止

新舵机模式中，已认证 `MANUAL` 会话绑定 `MANUAL_SERVO_VELOCITY`，`AUTO` 为未来位置策略预留。策略不能由普通消息、自报 mode 或编码器上线自动切换。协调器和执行端均校验命令类型、策略和能力；保持旧双轴 CLI 已有契约，不顺带全局改变其 MANUAL 下的旧调用行为。

保留单一在途许可与容量 1 最新命令槽。输入、许可、执行租约和输出各自期限取约束最严者，并保留最初的截止时间；定时器、迟到回执和持续读遥测不能续活旧命令。STOP 独立撤销待发目标、许可和输出；旧代次命令及迟到 ARM 回执不得恢复力矩或运动。

速度模式初始化必须执行并记录：

1. 识别实际设备，读取模式、Drive Mode、力矩、watchdog 和错误；先确认 Torque Off。
2. 仅在模式确有变化时写入速度模式 1，减少 EEPROM 重写；核对 Drive Mode，禁止叠加隐含反向或自动使能力矩行为。
3. 按厂家规则应用并读回速度限制、加速度、非零 watchdog，写入并确认零目标，保持 DISARMED。不得继承历史非零 Goal Velocity。
4. 显式 ARM 前重新确认零目标、当前配置、有效新鲜反馈、会话和输入资格，再使能力矩。watchdog 锁存和硬件故障需要显式恢复，不在 configure 中无提示自动清除。
5. STOP 零速写入失败时仍独立尝试关闭力矩。停止成立必须依据新鲜速度／力矩及预声明的判据；只有通信写回执或反馈已失效时，不宣称停止确认，报告 UNKNOWN。

串口 I/O 所有者独立执行命令截止检查。Bus Watchdog 会被状态读取维持，因此“控制计算停滞但遥测仍继续”必须主动撤销输出，不能只依靠总线 watchdog。全进程通信停止的设备行为另有独立证据。

正常退出顺序为停止、确认、DISARM、释放会话、关闭节点和串口。配置成功后保留速度模式 1，不在 STOP 或退出时恢复模式 4，也不恢复旧非零目标；日志记录持久配置变化。清理中任何失败均保留实际结果，不写成已安全完成。

未来策略交接必须经过 STOP 确认 → DISARM → 结束旧任务并撤销旧会话／许可 → 建立新会话和策略 → 启用所需采样并建立参考 → 显式 ARM。首期位置策略不可用，应在使能前明确拒绝；不得以实现接口为由提前开放其能力。

## 六、外部编码器与 PID 的预留边界

本轮交付明确类型和语义的反馈端口、机械换算契约和位置策略接口；不添加返回零的占位编码器，不填写未经测量的硬件增益，不实施编码器驱动或实际闭环。

- 外部反馈包含位置／速度及各自有效性、样本序号、设备代次、原始采样时间和参考版本。未来复用 `LinearEstimator` 处理计数、回绕、参考、跳变和时间检查。
- 相对目标从正式接纳任务时的新鲜外部位置建立；绝对目标要求匹配 `reference_id`。失效、过期、跳变或未标定时拒绝／中止位置任务，不自动降级为手柄速度控制。
- 控制结构为位置 PID 输出 mm/s，再经实测 mm/转和方向换算为 RPM，交给舵机内部速度环。不默认叠加外部速度积分环，不把该 PID 接入手柄路径。
- 复用 `PositionController` 的位置误差、速度前馈、测量微分和抗饱和设计；每个新有效外部样本至多更新一次，使用真实采样间隔。速度、加速度、位置边界和寄存器量化的最终影响均可回传，量化残差只结算一次。
- 预留 `reset`、`update_target`、`step`、`commit_limited_output`、`observe_accepted_output`、`stop` 的清晰契约。STOP、故障、参考／配置／策略变化清除积分、目标和待发输出。
- 未来到位需同时满足轨迹结束、真实位置误差、有效速度阈值和驻留时间，停止确认独立记录。先整定 P，必要时增加 I，D 初始关闭；当前不宣称 PID 硬件整定完成。

1. 先核实接收器实际模式并预声明失联界限 D；用现有只读资格流程检查手柄断电、无线失联、接收器拔出，每类 3 次，共 9 次。任一项失败即结束本轮资格流程并保留失败证据，不反复尝试到偶然通过。已有与当前身份、模式、驱动及 profile 一致的有效证据可以复用，不重复标定已确认的按键。
2. 保留现有 hardware 对 `joydev + qualified_state` 的要求。不延长 `event_age` 绕过限制，不伪造资格，不把真实手柄改称 `PROGRAMMED_JOG` 或脚本输入。资格缺失时真实手柄运动入口保持关闭。
3. 在用户已授权的空载设备条件仍成立时，先记录最大 RPM、单段持续时间、停止阈值和超时，开展一轮有限低速验证，覆盖正反转、不同杆量调速、LT/B 和正常退出。将下述两个短失效场景各做一次，合并在同一轮验证中；普通 SDK 错误、写入失败等分支只做软件注入，不逐项制造真实故障。首次上电不自动运动，不追加无关的大角度、长时间试转。
4. 第一种场景停止控制命令更新但保持遥测，验证 I/O 所有者按原命令截止时间主动停车，并用新鲜反馈确认。第二种场景在完成在途事务后暂停全部总线通信，验证设备 watchdog；恢复时首先只读锁存、速度和力矩，不先写零或关闭力矩再宣称 watchdog 自行停车。确认有独立结束运动的条件后才执行这两项。首次可信零速读回只证明截至该次采样已经停止，不倒推精确停时；超过预声明上限则该时限验收未通过，无可信反馈则停止状态 UNKNOWN。受控总线静默不等于真实进程崩溃或操作系统冻结已经验证，不扩展到此类试验。未实测项标为 NOT_RUN。
5. 缺少操作者按键／断电配合、设备模式或其他必要实物条件时，提出具体缺项，停止依赖该条件的动作，同时完成不依赖它的软件和文档工作。时间经过不等于操作者已执行动作，不能无限等待或循环采集。

既往“空载、方向与角度不限”的授权不等于速度模式与失效停止已经验证。沿用现有授权和已确认条件，不重复索要相同许可；出现负载、接线或设备身份变化时先核实事实。不得用系统权限变更、关闭门控或伪造原双轴 HIL 通过来解决启动问题。

故意触发 watchdog 后，目标寄存器可能已锁存为只读；此时保留故障、关闭力矩并记录新鲜停止证据，或通过单独明确的恢复步骤清锁后再验证零目标。通用清理不得自动清锁或恢复历史速度，不能同时要求“保留锁存”与“必须写零成功”。

## 八、记录、文档和完成判定

在 `artifacts/servo_ros2/` 下为本次运行建立独立记录目录，保存配置摘要、构建／测试命令及退出码、软件版本、实际设备身份、模式与关键寄存器读回、输入资格来源和失败原因。记录具有明确时间与单位的原始 LY、映射值、策略、目标／接受／实测 RPM、舵机轴计数、力矩、错误、输入年龄和停止原因；日志不得输出授权 token，不伪造毫米位移。

补充用户可照做的独立配置导出、ROS 模拟启动、真实舵机启动、同 owner 管理、手柄操作、停止退出和记录查看步骤。更新必要的架构、ROS 接口、手柄指南、配置及实现状态文档。实际命令须与本次安装入口一致；launch 默认不自动授权或运动。原双轴 HIL 保持原范围，新增舵机专项证据，不将尚未连接的设备标为已通过。

最终按下列三项分别给出 PASS／FAIL／NOT_RUN、证据路径和缺项：

| 交付项 | 完成依据 |
|---|---|
| 软件实现 | 配置、原生驱动、纯舵机运行时、正式 ROS／手柄链路、必要定向测试与受影响回归通过；本次安装后的模拟链路运行成功，文档可照做 |
| 真实链路 | 输入资格有效，速度模式 1 的有界空载正反转与调速、LT/B、计划内停止检查均有原始证据，退出状态如实记录 |
| 后续接口 | 外部编码器与位置 PID 契约可评审，能力仍关闭，位移请求明确拒绝；不是实际位移闭环已完成 |

软件完成而真实链路未验收时，明确报告“软件完成，真实链路尚未验收”及具体原因，不把整体目标标记为完成。所有必需项目通过后停止测试并总结交付，不为了增加测试数量继续运行。
